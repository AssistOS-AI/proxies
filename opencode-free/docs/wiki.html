OpenCode Free Documentation

This page is the canonical source for OpenCode Free terminology used by the HTML documentation and design specifications.

OpenCode Free
OpenCode Free is the Ploinky agent proxies/opencode-free that serves OpenCode's zero-cost models as plain-text OpenAI chat models for Soul Gateway. It owns request validation, prompt flattening, the per-request CLI run, confinement, the service state and the model allow-list. It does not implement OpenCode's protocol, offer tool calling or vision, or choose a model for the caller.
OpenCode CLI
The OpenCode CLI is OpenCode's official command-line client, version 1.18.31, installed unmodified in the agent image from the GitHub release tarball whose SHA-256 is pinned. It is the only program that contacts OpenCode's service. The agent runs it non-interactively with run --pure --format json, the prompt on standard input, and a throwaway home, data, state, cache, temporary and working directory per request.
AgentServer
AgentServer is the Ploinky runtime process that serves the agent's HTTP port. It runs the command handlers declared in manifest.json for Chat Completions and Models requests, passes them the request on standard input, and turns a handler's failure envelope into the HTTP status, error type and retry hint the caller receives.
Confinement
Confinement is the rule that the CLI's built-in tools stay defined in every request, because OpenCode's service refuses free-tier requests without them, but can never run. The baked configuration sets "permission": {"*": "ask"}, the run omits --auto so every permission request is rejected, and the handler fails the request closed on any attempted tool, any unfinished answer or any reported cost. The container is the second layer.
Service state
The service state is the agent's record, in /data/service-state.json, of whether OpenCode's service answers the agent's request shape at zero cost: unverified, verified, refused, unavailable or tripped. A background probe loop sets it from one live request at container start and from later re-probes; handlers can only raise it to refused or tripped. Chat requests and the model list are served only in verified. Ploinky readiness does not depend on it.
Allow-list
The allow-list is the fixed set of seven free model ids, with their context windows and output limits, that the agent serves for the reviewed CLI version. With a key present the CLI would also run priced models, so any model outside the allow-list is rejected before the CLI starts. A model the service reports as not found is disabled until the container restarts.
Flattened prompt
The flattened prompt is the single text the agent writes to the CLI's standard input: an optional System instructions: block followed by User: and Assistant: blocks in message order. Flattening loses the role boundaries, the client's system prompt precedence, names, tool history, non-text parts and sampling parameters.
